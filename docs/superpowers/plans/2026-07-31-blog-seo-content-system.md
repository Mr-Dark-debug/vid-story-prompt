# Vidrial Blog and SEO Content System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and verify Vidrial's text-first blog platform, technical SEO surface, reader feedback, IndexNow workflow, and a reviewed 60-article Markdown library.

**Architecture:** Strict Markdown frontmatter is parsed and validated at build time, then served through TanStack Start server functions without article database reads. Shared blog components render the index, category, and article routes inside the existing marketing shell. Supabase is limited to reader feedback and durable IndexNow reconciliation logs.

**Tech Stack:** TanStack Start/Router, React 19, TypeScript, Zod, gray-matter, react-markdown, remark-gfm, Supabase/PostgreSQL, Vitest, Playwright, IndexNow.

## Global Constraints

- Canonical production origin is exactly `https://vidrial.vercel.app`.
- Do not edit `src/routeTree.gen.ts`; let TanStack Router regenerate it.
- Use `src/components/primitives/logo.tsx`, existing semantic CSS tokens, Manrope fallback, and restrained Coral.
- Do not render article hero images, inline images, placeholder image frames, or a browser/screenshot container.
- Do not expose service-role credentials, permanent provider tokens, private URLs, transcripts, filenames, or raw anonymous identifiers.
- Only articles with `reviewStatus: PASS` and `draft: false` may appear in public lists, internal recommendations, RSS, or sitemaps.
- Claims about Vidrial must match `src/domain/features/availability.ts`, `src/domain/clipping/entitlements.ts`, the connector registry, and `PRODUCT_SPEC.md`.
- Never fabricate testing, statistics, author credentials, search-engine registration, deployments, or provider success.
- Preserve existing client rotation, IPv4 enforcement, and `YTDLP_PROXY_URL` behavior in the video worker.
