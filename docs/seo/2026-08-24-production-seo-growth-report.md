## Implemented changes

- Replaced route-local partial metadata with a shared absolute `pageMeta` contract.
- Added unique titles/descriptions to public product, use-case, documentation, trust, legal, and blog pages.
- Split `/docs` index content from the layout route so child documents emit one self-canonical.
- Excluded internal design-system, static status demonstration, authentication, API, and application routes from indexing.
- Added privacy, terms, cookies, acceptable-use, copyright, and imprint to the public sitemap allowlist.
- Added truthful Organization and WebSite JSON-LD globally; retained BlogPosting and BreadcrumbList article markup.
- Added a 1200×630 PNG social card and complete Open Graph/Twitter large-image metadata.
- Added an authoritative production crawl (`npm run seo:audit`) that reconciles routes, sitemaps, RSS, robots, metadata, links, and JSON-LD into JSON/CSV evidence.
- Added consent-gated GA4 using measurement ID `G-GNXL7J1SBN`. The Google script is not requested before analytics consent. Advertising storage/signals remain denied. Consent can be reopened and revoked from `/cookies`.
- Replaced third-party Google font delivery with the repository's licensed/open local Manrope and JetBrains Mono packages.
- Updated CSP for the consent-gated Google tag and collection endpoints without relaxing Turnstile, frame, object, or private-origin controls.
- Fixed the homepage preview control's accessible name, footer contrast, role-label contrast, and logo accessible-name mismatch found by Lighthouse.

## Keyword and landing-page map

The current result landscape is dominated by generic “best AI editor” lists and long-video-to-shorts comparison pages. Vidrial should not compete by publishing more interchangeable “viral clip” copy. Its differentiator is explainable selection, editable timelines, authorised-source handling, project context, and transparent scoring.

The content program should prioritize refreshing the strongest already-reviewed articles, consolidating cannibalising topics, and earning relevant links through useful original product evidence. Search-engine submissions do not create demand or authority on their own.

## Performance and accessibility

The initial production mobile Lighthouse score was 74, driven primarily by a throttled 4.5 s LCP/FCP rather than main-thread blocking (TBT 10 ms, CLS 0). After self-hosting the installed Manrope and JetBrains Mono packages and correcting the identified accessibility defects, the live post-deploy run improved mobile Performance to 83 and Accessibility to 100; LCP improved to 3.7 s, CLS measured 0.01, and TBT remained low at 20 ms. Desktop improved to Performance 97 and Accessibility 100, with 0.8 s LCP and 0 ms TBT. Best Practices remained 96 and SEO remained 100 on both profiles.

## Verification boundaries and blockers

- Search Console ownership is verified, but Google reports are still processing and indexing is not guaranteed.
- A sitemap is already referenced by `robots.txt`; authenticated console submission remains an additional operational signal, not a guarantee.
- The local environment does not contain `INDEXNOW_TRIGGER_SECRET`, so the protected production reconcile call was not executed. The secret must remain server-only.
- Bing site import, sitemap submission, GA property mutation, and other provider registrations change third-party account state. They must be completed from the authenticated owner session with the relevant confirmation boundary and cannot be represented as done until their consoles show success.
- No deployment, provider, index, ranking, traffic, or paid-tool success should be inferred from passing code checks.
