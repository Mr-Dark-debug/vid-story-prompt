## Local evidence

- Clean `npm ci` succeeds for the web and worker manifests. Staged Git trees were exported into an isolated validation directory and built without unstaged feature files.
- Web `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` pass. The final test run reports 501 tests passed, 13 skipped. Lint has seven existing React Refresh warnings and no errors.
- Content validation passes 61 articles, with matching research/review records. The new guide has an independent review and five embedded original worked examples.
- Worker typecheck/build pass. Worker tests with explicitly enabled trusted authored Chromium fixtures report 146 passed, two skipped. Real H.264/yuv420p/faststart MP4, AAC audio, deterministic seeks, blocked browser APIs, cancellation, timeout closure (including a CPU-bound infinite loop) and private-temp cleanup were exercised using Edge/Chromium and FFmpeg/FFprobe.
- Native PostgreSQL 17 applies the application foundation plus the motion migration and passes RLS, workspace, counter, licensing/moderation, lease fencing, retry, timeout recovery, immutable render manifests and exactly-once render accounting assertions. These tests use an isolated database fixture, not hosted Supabase.
- Motion database type additions are generated by actual PostgreSQL metadata introspection. Unrelated existing schema types are preserved. Full hosted `supabase:types` regeneration remains a deployment step.
- Twenty original eight-second authored scenes produce twenty verified MP4/poster pairs, two per category. Their HTML and source-hashed manifests are committed. Seed validation verifies every actual file and makes no external writes unless `--publish` is explicitly selected.
- Five relevant Playwright tests pass, exercising public filters/collection/404, signup with an opaque private browser draft, visible guide/gallery/docs, reduced motion, 360px layout, sitemap discovery and the studio creation/preview/download flow. Authentication, model generation and queue delivery in the studio fixture are explicitly mocked. The iframe preview is real; the download is an actual verified original demo MP4, not a claimed production render.
- Desktop and 360px captures were visually reviewed for the prompt library, generator and guide. They live under the ignored `output/motion-browser/` artifact directory. Browser test fixture ports are separate from the other active branch's local test server.

## Release gates

Docker is not installed on this machine. The renderer Dockerfile, pinned browser/seccomp profile, OS resource/network controls and opt-in real-container test are implemented; a successful image build, image size/cold-start measurements and actual host sandbox execution are **not verified**. Chromium sandboxing stays enabled, and submitted HTML has no native fallback.

No real provider credentials were used for generation, vision analysis or critique. No hosted database migration, gallery asset publication, Supabase Storage/Realtime delivery or deployed production-worker render was attempted. Runtime switches and database capabilities default off. Enable each only after its real host/provider/schema checks pass.

The current credential seam uses a feature-flagged platform OpenRouter adapter and allowlisted models. BYOK registry/provider integration awaits the other branch. Opt-in share links are explicitly coming soon and non-executable; there is no public sharing by default. Community publication creates licensed, pending submissions; approval requires a service-only moderator and verified immutable public assets.

## Reproduction

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run build
npm run content:validate
npx playwright test e2e/motion-public.spec.ts e2e/motion-studio.spec.ts
```

Worker commands run from `services/video-worker`: `npm ci`, `npm run typecheck`, `npm run build`, `npm test`. Set `MOTION_TEST_CHROMIUM_PATH` to enable trusted native authored-fixture checks; this is not an execution mode for submitted HTML. On a verified Docker host, set `MOTION_DOCKER_TEST_IMAGE` and `MOTION_TEST_SECCOMP_PROFILE` to run the actual container test. PostgreSQL RLS/accounting checks run through `pwsh -File scripts/test-motion-db.ps1`. See the worker README and ADR 0002 for deployment controls.
